# Phase 7 agent evaluations

`packages/agents/src/evaluation.ts` defines the versioned `phase7-v1` deterministic suite and its runner contract. Fifteen fixtures cover product price and availability, a three-message burst, image and voice input, returns, complaints, ambiguity, unknown information, approved browser lookup, handoff, tool/provider failure, model timeout, and comment reply/review outcomes. An execution adapter receives the immutable candidate version plus one fixture and returns only a safe status, allow-listed action/outcome types, and an optional safe failure code.

The runner checks required and forbidden outcomes, action-count limits, expected run status, and regressions against the preceding run for the same immutable version. Each result is bound to the candidate configuration revision; changing a draft makes the previous run stale. Publishing checks the revision again in the same transaction that changes the active pointer, closing the edit-after-evaluation race. Persisted results contain the version/business IDs, suite version, revision, timestamps, case IDs, safe action types/statuses, failed check codes, and regression case IDs. Fixture text, prompts, model context, replies, tool arguments, and hidden reasoning are never stored. The latest result must pass the current suite and compatibility checks before `AgentVersionService.publish` selects that version.

`AgentRuntimeEvaluationAdapter` sends each fixture through the normal event validation, trusted-context, context-building, model-provider, action validation, trace, and run-status paths. It runs with the `evaluation` system principal and `draftOnly`, which hides tools and suppresses external action execution. Tests use deterministic fake provider responses and assert fixture input reaches runtime context and no actions escape. Agency operators can run the suite from a saved draft using the business-scoped Agent Versions UI. That run uses the server-configured OpenAI-compatible endpoint and the candidate's saved primary/fallback model selection; the model-timeout case injects a deterministic provider failure. Browser/tool actions remain suppressed, so these cases validate safe AgentRuntime behavior and candidate response behavior without executing external tools. Model calls can incur provider cost. The image fixture is currently a text prompt without an image payload; provider vision compatibility is validated separately by the provider probe.

`agent_evaluation_runs` is additive migration `0017_gigantic_wonder_man.sql`. The Postgres result repository verifies the business/agent/version relationship before inserting a result, and reads the latest result within business and version scope. The runner is adapter-based so a controlled fake can exercise deterministic regression checks without sending customer actions.

Version administration covers atomic agent-plus-initial-draft creation, immutable published snapshots, optimistic draft revisions, explicit test selection, evaluation, publication, rollback to a previously published snapshot, archive, and audit. Published and archived snapshots remain immutable. The operator UI edits the validated configuration JSON, shows safe case results, and only exposes publish when the latest suite passed for the current revision.

Validation:

- `bun test tests/phase7-evaluations.test.ts tests/agents-auth.test.ts` checks fixture coverage, safe persistence shape, forbidden actions, regression diffs, and publish blocking.
- `bun test tests/phase7-evaluations.test.ts` also drives all 15 fixtures through `AgentRuntime` with a deterministic fake provider, confirms the input reaches current-event context, and checks external action execution stays suppressed.
- `DATABASE_URL=<disposable PostgreSQL URL> bun run db:migrate` applies the additive migration.
- `DATABASE_URL=<disposable PostgreSQL URL> bun run db:phase7-evaluations` checks atomic agent/draft creation, business scoping and capability enforcement, safe result round-trip, regression handling, stale-revision publish denial, optimistic editing, test selection, successful publish, rollback, archive, audit, and cleanup.

The disposable Postgres integration supplies deterministic expected outcomes so repository and version lifecycle checks do not require a live provider. The agency UI can run model-backed candidate evaluations when configured, but a live model quality comparison still requires the approved endpoint and representative approved test data. The fixture suite does not provide an image payload or execute browser/tool actions.
