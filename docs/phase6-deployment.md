# Phase 6 deployment

Use Bun 1.3.14 or newer, PostgreSQL, Redis, a public HTTPS admin app, and a private writable media directory shared by the admin app and queue worker. Run `bun install --frozen-lockfile`, `bun run db:migrate`, `bun run admin:build`, `bun run client:build`, and `bun run worker:start`. The worker composition requires real Meta, model, vault, and media configuration in `.env.example`; it does not register the test Web Chat adapter or a fake model.

## Meta app and Page

Configure `META_APP_ID`, `META_APP_SECRET`, `META_OAUTH_REDIRECT_URI`, `META_WEBHOOK_CALLBACK_URL`, and a random `META_WEBHOOK_VERIFY_TOKEN`. Add the callback under the Meta App Messenger webhook settings and select message, delivery, read, and postback fields. Set the Page token through the authorized agency Messenger screen or use its OAuth Page picker. The agency screen keeps the Page pending until token identity, app handshake, Page subscription, an inbound test message, and a controlled reply succeed. The first test conversation stays paused after activation. A human must resume it explicitly if desired. Obtain the applicable Meta app review/advanced access for `pages_messaging`, `pages_show_list`, and `pages_manage_metadata` before public use.

`CREDENTIAL_ENCRYPTION_KEY` must be 32 random bytes encoded as 64 hex characters and must be backed up outside the database. `CREDENTIAL_KEY_VERSION` identifies the active key. Rotation requires a deliberate re-encryption procedure before switching versions. Page access tokens and media URLs are encrypted with AES-256-GCM and are only decrypted inside the adapter or media worker. Configure `META_MEDIA_ALLOWED_HOSTS` as an exact comma-separated list of Meta CDN hosts observed for the deployment; unexpected hosts fail closed. Meta Page token renewal and permission loss surface as `NEEDS_REAUTHORIZATION`.

## Media

Set `PRIVATE_MEDIA_DIR` to a private persistent volume shared by the app and worker. The worker downloads signed Meta media with pinned public DNS, validates content and size, writes it to that directory, then runs the configured vision, transcription, or document adapter. `OPENAI_VISION_MODEL` names an approved vision capable model; `ELEVENLABS_API_KEY` enables audio transcription. The public `PUBLIC_MEDIA_BASE_URL` must be the admin app's HTTPS origin. `MEDIA_SIGNING_KEY` signs short lived read URLs for images sent through Meta. The `/api/media/...` route checks signature, expiry, tenant key, and attachment readiness. Restrict filesystem permissions to the app and worker principals.

## Browser isolation

Set distinct random `BROWSER_WORKER_TOKEN` and `BROWSER_EGRESS_TOKEN`, then start `docker compose -f docker-compose.browser.yml up -d --build`. Point the main worker at `BROWSER_WORKER_URL=http://127.0.0.1:4317`. The host port belongs to a narrow bridge in the egress container; Chromium runs only in the internal browser worker container. That worker has no database, Redis, Meta, OpenAI, or media credentials. It has a read-only root, ephemeral profile and screenshot volumes, dropped Linux capabilities, a process and memory limit, and an internal-only Docker network. Chromium uses a per-session HTTPS CONNECT proxy with exact approved hosts and public IP checks. CDP also intercepts page requests. Uploads, downloads, non-HTTPS navigation, private IPs, and unapproved hosts are denied. Sessions expire and kill Chromium. Screenshots stay in the worker's private ephemeral volume and only an opaque reference reaches AgentOS.

Browser Use Pi was evaluated against its official TypeScript quickstart and browser API. The current API uses accessibility/coordinate controls and generated JavaScript for general work; it does not expose the existing selector based `click`, `type`, and `extract` contract. Its generated JavaScript can access the worker filesystem and network if run without additional isolation. This implementation uses the Browser Use ecosystem's documented CDP approach with a small fixed-operation TypeScript CDP adapter, preserving the existing BrowserAdapter and runtime interfaces. It does not use Browser Use Cloud. The local test override at `tests/browser.compose.yml` must never be used in production: it enables a self-signed controlled site and a test-only certificate bypass.

## Operations

Run `bun run check`, `bun run db:phase5-smoke`, and `bun run db:phase6-messenger` against a disposable PostgreSQL/Redis installation after migration. For the controlled browser test, generate a short lived certificate for `browser.test`, set `BROWSER_TEST_CERT_DIR`, use the test compose override, and run `bun scripts/phase6-browser-integration.ts` with the test worker token. Monitor `channel_connections` state/last error, `messenger_sends` UNKNOWN rows, `effect_intents` UNKNOWN rows, work dead letters, browser worker health, and media FAILED rows. An unknown Meta send must be reconciled by external evidence or operator action before retrying. Never convert an unknown result to a second send automatically.
