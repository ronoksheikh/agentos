# Phase 7 health and readiness

Migration `0015_glossy_microbe.sql` adds `service_heartbeats`. Each queue worker writes one heartbeat at startup and every 20 seconds, then removes it during graceful shutdown. The agency System Health view counts worker instances seen in the last 90 seconds. A stale row after a crash is ignored; the row contains only instance ID, service name, and timestamps. Workers also publish OpenAI model circuit state using a separate heartbeat. The breaker opens after three consecutive retryable failures, fails fast for 30 seconds, then allows one half-open probe. Successful or non-retryable responses close the circuit; canceled requests do not count as failures. Health reports the circuit open if any live worker is open and unknown when no live circuit heartbeat exists.

`GET /api/health/ready` returns only `{ "ready": true|false }` and HTTP 200/503. Readiness requires a reachable PostgreSQL database with the heartbeat schema migration and a Redis PING. It does not expose connection strings or diagnostics. The agency System Health page requires `queue.read` and shows database/Redis reachability, worker heartbeat count, Browser Use `/health` reachability when configured, model circuit state, global durable work state counts, channel connection states, and whether provider configuration is present. It never displays secrets, provider URLs, raw errors, or business content. A configured provider label is not a successful live probe; provider acceptance remains separately gated.

Operators should alert on no live worker heartbeat for 90 seconds, failed readiness, dead work increasing, disconnected/reauthorization-required channels, or unavailable Browser Use when configured. The existing Events & queues page provides business-scoped failure codes, lag, dry-run replay, and reconciliation controls. Browser Use is a separate executor; its health check does not prove a model-backed browser task completed.

Validation: migration `0015` applied on an upgraded and a fresh disposable database. `scripts/phase7-health-integration.ts` checks schema/Redis readiness, live versus stale worker heartbeat, closed/open provider circuit heartbeat visibility, malformed browser address handling, and redacted output. The Phase 5 PostgreSQL/Redis integration was rerun with actual worker start/stop assertions for heartbeat insertion and removal. Its historical comment assertion now expects fail-closed `COMMENT_PROCESSOR_UNAVAILABLE` when no Phase 7 comment processor is registered.
