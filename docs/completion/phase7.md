# Phase 7 implementation and verification report

**Status: not complete; release blocked.** The Phase 7 implementation has substantial offline coverage, but this report does not declare the phase complete or authorize production rollout. Live provider, merchant-site, and Meta acceptance checks remain unavailable.

This report records repository state and evidence as of 2026-09-28. The upstream `browser-use/browser-use` repository was not modified; AgentOS pins and runs its open-source package in the isolated worker.

## Delivered modules and contracts

- **Browser Use:** Production composition replaces the Phase 6 raw CDP/Chromium worker with `browser-use==0.13.10`, its supported `browser-use install` browser provisioning, the existing TypeScript `BrowserAdapter`/coordinator/tools/jobs boundary, and a narrow authenticated egress/model gateway. Browser Use Cloud and Pi are not configured. Session isolation, per-session HTTPS egress, domain and action limits, deadlines, cancellation, safe progress, private ephemeral screenshots, restart recovery, and untrusted page content are documented in `docs/phase7-browser-use.md`.
- **Removed browser implementation:** Commit `ffd4360` deleted `apps/browser-worker/Dockerfile`, `apps/browser-worker/src/cdp.ts`, and `apps/browser-worker/src/index.ts`. The former `apps/browser-worker/src/egress.ts` became the generic `apps/browser-egress/src/index.ts`; the Python worker is `apps/browser-use-worker/worker.py` with its own Dockerfile. The old `browser-worker:start` script and `BROWSER_CHROME_PATH` configuration were removed. Generic contracts and deterministic test fakes remain.
- **Providers:** The official OpenAI TypeScript SDK is behind existing model and vision interfaces. The worker configures `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`, optional `OPENAI_FALLBACK_MODEL`, `OPENAI_VISION_MODEL`, and `OPENAI_TIMEOUT_MS`; it probes required endpoint capabilities and uses the approved primary or configured vision fallback. Published agent instructions remain authoritative. Optional `OPENAI_CLASSIFIER_MODEL` selects a structured comment labeler and is probed at startup for JSON category output; model labels are review-only and fall back to deterministic rules on provider or parsing errors. ElevenLabs transcription is configured through `ELEVENLABS_API_KEY`, `ELEVENLABS_MODEL`, `ELEVENLABS_ENDPOINT`, and `ELEVENLABS_TIMEOUT_MS`. Safe placeholders are in `.env.example`; no real credentials were committed. Mock endpoint/provider tests passed; live endpoint compatibility and transcription remain unverified without approved credentials and samples.
- **Real Website Chat:** Production composition registers `WebChatAdapter` with durable visitor sessions and the shared universal event/action worker path. Public routes are `POST /api/web-chat/v1/bootstrap`, `GET|DELETE /api/web-chat/v1/session`, and `GET|POST /api/web-chat/v1/messages`. Exact origins, signed visitor sessions, tenant/site/agent binding, expiry and revocation, rate limits, ordered/deduplicated inbound messages, idempotent outbound delivery, and text-only attachment rejection are enforced. An assigned staff member can take over a handoff and send idempotent text replies through the active visitor poll session. The fake adapter remains test-only.
- **Facebook comments:** Signed Page feed additions enter the shared event router and typed `CommentProcessor`. The processor loads scoped post data, verified same-post parent text, and manager-mapped one-item catalog text pinned to the approved catalog version; it classifies into bounded typed outcomes, applies conservative policy, and routes allowed AI replies through the same runtime in `draftOnly` mode and a server-bound `ReplyToComment` action. Verified reply/hide capabilities, author checks, handoff ownership, idempotency, review, audit, client-safe realtime, business-scoped analytics, and authorized manager manual reply/hide controls are implemented. Deletion is an explicit manager-only manual action: it requires a successful controlled `can_remove`/Graph DELETE test, a separate saved policy, `channel.manage`, per-comment confirmation, current Graph `can_remove`, and verified Page post/author scope. It is audited and idempotent, clears locally stored text after success, and remains unreachable from classifier decisions. Default automation and deletion policy are off. Live Meta permission acceptance remains open; see `docs/phase7-comments.md`.
- **Operations and client features:** The one-calendar-month trial lifecycle has audited agency controls, notifications, and no automatic data deletion. The agency home page reports live business, unread, handoff, and failed-run aggregates with defined grains and windows; client analytics include scoped operational counts and a documented 30-day delivery-qualified first-response/handoff cohort. The agency Usage page reports persisted run token totals, completed model calls by provider/model, comment-classifier response tokens by business/agent/provider/model, tool calls, and browser activity over a rolling 30-day UTC window. Classifier counts are separate from runtime totals, exclude comment content, and include only calls with provider-reported usage; no dollar estimates are shown. Agency Runs, Browser Runs, Handoffs, Integrations, Agents, Tools, Audit Logs, and Team pages now read bounded live database records, redact credentials, page content, and freeform customer text, and show explicit empty/error states. Agency users can create audited, 72-hour agency invitations and business-scoped client invitations through the configured email gateway; the raw token is stored only as a hash and carried in a URL fragment removed from browser history on acceptance. The Businesses page lists live business/onboarding/trial state and permits authorized creation in a safe `PAUSED`/`CREATED` state with an audit row. Business workspaces now support audited agent creation with an initial draft, revision-checked JSON editing, explicit test selection, model-backed evaluation through `AgentRuntime` with external tools/actions suppressed, compatibility checks, gated publish, rollback to previously published snapshots, and draft archival. Evaluation results are bound to the tested revision and publish rechecks that revision inside its pointer transaction. A controlled interactive model playground remains unavailable. Unfinished generic navigation sections no longer display sample data as if it were live. In-dashboard notifications now have per-user/business isolation and producers for handoffs, stale handoffs, terminal run failures, dead queue work, Messenger reauthorization, comment review, and trial lifecycle events. Feature flags gate browser, comment AI, advanced memory, experimental tools, and per-business fallback-model rollout at runtime; global and business overrides are revision-checked and audited. Experimental tools also require explicit agent tool selection and their other capabilities and policies. Runtime model variants use a configured same-provider fallback without mutating the saved agent version. The 15-case evaluation suite gates publication. Worker readiness/heartbeats and provider-circuit health are exposed. Retention, offboarding, and PostgreSQL/private-media backup/restore procedures have disposable-database drills.

## Security and operational decisions

- Secrets stay in server environment/vault paths. The Browser Use container does not receive database, Redis, Meta, ElevenLabs, or general vault credentials. No changes are made to the upstream Browser Use repository; its pinned published package is installed in AgentOS's isolated Docker image. Its optional research model uses a narrow gateway with public-DNS pinning and a single approved Chat Completions model.
- Browser uploads/downloads are disabled. Screenshot bytes remain private and ephemeral; only opaque IDs can be returned. No stealth, CAPTCHA, proxy anonymity, or cloud-service guarantee is claimed.
- Comment and Website Chat content remains untrusted. Optional model classifier labels are review-only and policy returns keep/review before any write action. Comment deletion is manager-only, explicitly confirmed, capability/policy gated, and never automated; ambiguous external writes are not blindly retried. Uncertain comments default to keep/review.
- Client reads and notifications filter by authenticated business and, for inbox rows, authenticated user. Notification payloads are not projected to the client. Acknowledgement rechecks membership and capability.
- Invitation issuance checks `agency.manage` or `business.manage`, stores only SHA-256 hashes of high-entropy single-use tokens, rejects current members and concurrent live invitations, and conditionally expires unaccepted invitations after delivery failure while recording a content-free audit. If a link was accepted during an uncertain gateway response, its accepted state and expiry remain unchanged. Acceptance links carry tokens in fragments, which browsers do not send in HTTP requests; the acceptance pages clear the fragment from browser history after loading it.
- Retention is opt-in and bounded. Checkout fields on terminal orders/closed pending orders, order-note text, closed goal content, expired announcement content, and older safe audit metadata have configurable age rules. Financial order/item/audit records, active order/checkout data, active goals/executions, audit event identity, retention-policy audit metadata, external identity keys, and backup copies remain intact pending accounting, operational, and legal-hold schedules. Legal erasure is not claimed until external providers and backup copies are covered separately.
- Backup manifests detect accidental corruption, not malicious replacement. The local file-backed media copy is not an atomic shared PostgreSQL/object-store snapshot; the runbook requires draining writers for strict restore points.

## Open release gates and limitations

1. **Live OpenAI-compatible endpoint and ElevenLabs:** Supply approved development/staging/production credentials and endpoint/model choices, verify Responses, tool calls, structured output, images, and transcription against those exact services, then record observed results. Mock compatibility is not live acceptance.
2. **Live Meta Page:** Supply an approved Meta app and authorized Page/token with the required scopes, subscribe the Page feed, receive a signed controlled comment, run read/reply/hide/delete tests on operator-created comments, observe each Page result, and verify Page-authored replies do not loop. This was not available, so no live Meta write or deletion permission is claimed.
3. **Website Chat acceptance:** Embed the production SDK on an authorized merchant staging site, verify origin/CORS and visitor experience, and observe a human reply through its polling client. Local HTTP tests are not merchant-site acceptance.
4. **Browser model-backed research:** Supply an approved compatible endpoint/key and verify bounded `browser_research` output on a controlled site. The AgentOS Responses probe does not establish Browser Use Chat Completions compatibility.
5. **Comment workflow gaps:** The optional model classifier is review-only and has no production quality comparison. Live Meta app/Page validation, including comment deletion permission, is still required before release.
6. **Analytics limits:** Validated conversation question categories, customer objections, attributed conversion/revenue, and dollar cost estimates are unavailable in the persisted source data. Classifier labels remain review-only and have no production quality comparison. Do not infer business outcomes or costs from comment categories or unrelated orders.
7. **Flag rollout evidence:** `experimental_tools` and `runtime_variant` have server-side consumers and are visible as audited global/business-scoped controls. Offline paths are covered; live staged rollout still requires an approved model endpoint and a controlled business with compatible fallback models and experimental tool policy enabled.
8. **Retention scope:** Checkout contact fields on terminal orders/closed pending orders, order note text, closed goal content, expired announcement content, and old safe audit metadata have separate opt-in scrub rules. Financial order/item/audit records, active order/checkout data, active goals/executions, audit event identity, retention-policy metadata, and backup-copy retention still need policy review for accounting, operations, and legal holds. External identity keys remain for routing/dedupe.
9. **Invitation delivery:** Issuance uses the configured `AUTH_EMAIL_WEBHOOK_URL` and expects `agency-invitation` and `business-invitation` templates. The gateway and delivered email links require deployment verification; undeliverable invitations expire and are audited.
