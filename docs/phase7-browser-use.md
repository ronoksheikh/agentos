# Phase 7 Browser Use deployment

The production browser executor is the open-source Python `browser-use==0.13.10` package in `apps/browser-use-worker`. Its local Chromium is provisioned by the supported `browser-use install` command during the image build. AgentOS stays in TypeScript/Bun: `RemoteBrowserAdapter`, `BrowserCoordinator`, browser tools, jobs, tenant context, and safe progress keep their existing contracts. `apps/browser-egress` provides an authenticated host bridge and a per-session HTTPS CONNECT proxy. Neither Browser Use Cloud nor Browser Use Pi is configured.

## Configuration

Set independent random values of at least 24 characters for `BROWSER_WORKER_TOKEN` and `BROWSER_EGRESS_TOKEN`; set `BROWSER_WORKER_URL=http://127.0.0.1:4317` in the AgentOS worker. Run `docker compose -f docker-compose.browser.yml up -d --build`. Only the egress bridge publishes a host port, bound to loopback. The Python worker has no PostgreSQL, Redis, Meta, ElevenLabs, or AgentOS OpenAI key. Configure separate values for development, staging, and production, and rotate bridge tokens by replacing both containers and the AgentOS worker together.

Read-only `browser_research` is optional. To enable it, set `BROWSER_MODEL_BASE_URL` to an approved HTTPS OpenAI-compatible `/v1` base, `BROWSER_MODEL_ID` to an approved Chat Completions model, `BROWSER_MODEL_API_KEY` on the egress service, and a separate random `BROWSER_MODEL_GATEWAY_TOKEN` shared only between the Python worker and egress service. The browser worker calls `http://browser-egress:3128/v1/chat/completions` with the gateway token; the egress service swaps in the external key and pins a public DNS answer for that configured upstream. It allows only the configured model, non-streaming requests, and bounded payloads and response size. The browser agent is limited to the already-open page, at most three steps, and read-only extract/search/scroll actions. It cannot click, type, navigate, upload, download, or run arbitrary evaluation through that research operation. No endpoint or key means research fails visibly. Validate Chat Completions structured output behavior with the actual approved endpoint before enabling this tool in production; main AgentOS Responses compatibility does not prove Browser Use compatibility.

## Isolation and limits

Each browser session has a fresh private profile, exact HTTPS domain allowlist, IP-literal denial, deadline, action limit, and a dedicated egress proxy registration. The proxy checks the approved host and a public DNS answer before connecting. `maxEgress` bounds HTTPS CONNECT tunnel openings; HTTP requests multiplexed inside a tunnel are not counted individually. Upload and download support is disabled. The container uses a read-only root, ephemeral `/tmp`, screenshot, and home storage, a non-root user, dropped capabilities, and a two-session cap with 2 GiB memory and 1024 PID/thread limits. The higher PID limit was required by a measured two-browser run; the previous 256 limit caused `net::ERR_ABORTED` navigation failures.

Screenshots remain in the worker's private ephemeral filesystem, are removed on close/expiry, and are never returned as bytes to AgentOS. The client receives only an unrelated private screenshot ID. Browser content and agent research output are untrusted and sanitized at the coordinator boundary. The worker disables Browser Use telemetry and cloud sync. Self-hosting does not guarantee stealth, CAPTCHA solving, or a browser identity service.

## Validation and recovery

Use `tests/browser.compose.yml` only for the controlled test site. It enables a self-signed certificate bypass and serves `browser.test` from the egress container; never include this override in production. After generating a temporary certificate for `browser.test` and setting `BROWSER_TEST_CERT_DIR`, run `bun scripts/phase6-browser-integration.ts` with the test worker token. It covers open, extract, form input, click, screenshot reference, close, policy denial, cancellation, timeout, and safe realtime progress. Run `bun scripts/phase7-browser-restart.ts` with both test tokens and the certificate directory to check two-tenant page/screenshot isolation, rejection of stale sessions after worker restart, and a fresh open.

The browser container keeps session state only in memory. A restart drops the ephemeral profiles and screenshots. Stale remote session calls fail; the caller must open a new session. AgentOS persistence still records safe session and activity metadata and reconciles expired open rows on its own startup. Monitor `/health`, worker restarts, failed browser runs, and proxy capacity. The test override's certificate bypass and controlled-site DNS mapping must never enter production configuration.

The superseded Phase 6 `apps/browser-worker/src/cdp.ts`, `src/index.ts`, and multi-stage Chromium Dockerfile were removed after the controlled drills passed. `apps/browser-worker/src/egress.ts` became the generic `apps/browser-egress/src/index.ts` bridge/proxy. The old Bun `browser-worker:start` script and `BROWSER_CHROME_PATH` configuration are no longer used.
